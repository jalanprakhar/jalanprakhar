## Security Threat Model

**Trust boundaries:**
- Static portfolio code and local assets are trusted repository content.
- Outbound profile/resume/social links cross from the portfolio into external sites.
- Public contact details are intentionally visible only if represented in centralized constants.
- No backend, database, authentication, user-generated content, or form submission is introduced in Phase 1.

**STRIDE register:**
| threat_id | category | component | severity | disposition | mitigation_plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| TM-01 | Information Disclosure | `View Resume` CTA | medium | mitigate | Do not reference `/Users/ppjalan/Downloads/PRAKHAR.pdf`; use a centralized `resumeUrl` TODO or stable public URL only. |
| TM-02 | Spoofing / Tampering | External links | low | mitigate | Add `target="_blank"` only with `rel="noopener noreferrer"` and keep link destinations centralized for review. |
| TM-03 | Information Disclosure | Contact/footer shell | low | accept with control | Use only intentional public contact/profile data from constants; do not add private local paths or unreviewed personal data. |
| TM-04 | Denial of Service | Visual effects | low | mitigate | Use CSS-only restrained trace/status cues and respect `prefers-reduced-motion`; avoid heavy continuous canvas/SVG animation. |
</threat_model>
